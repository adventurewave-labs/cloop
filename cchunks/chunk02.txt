<section id="why">
  <div class="sec reveal">
    <div class="shead"><span class="gy">&#8505;</span><h2>why a loop</h2><span class="rule"></span></div>
    <div class="prose">
      <p>Headless Claude Code is a one-shot. The interesting behavior comes from putting it in a loop — let the model work, run a check, feed the result back, and let it try again. That outer loop is the thing you actually want to reuse, and it's the thing nobody wants to re-hand-roll as a throwaway bash script every single time.</p>
      <p>cloop is that loop, made reusable, inspectable, and saveable. You answer a few questions once, it writes a small TOML file, and from then on it's <span class="mono cyan">cloop run &lt;name&gt;</span>. It doesn't reimplement anything Claude Code does — it just composes the CLI and watches the exit code.</p>
    </div>
  </div>
</section>

<section id="stop">
  <div class="sec reveal">
    <div class="shead"><span class="gy">&#9679;</span><h2>stop conditions</h2><span class="rule"></span></div>
    <p class="lead">Three ways a loop decides it's finished. You pick one in the wizard.</p>
    
<div class="cards">
  <article class="card">
    <div class="cardTag mono">stop = <span class="str">"command"</span></div>
    <h3>until a check passes</h3>
    <p>Loops until a shell command exits <span class="mono">0</span>. Its combined output is fed into the next prompt, so the model sees exactly what failed. Best for test, lint, and build loops.</p>
  </article>
  <article class="card">
    <div class="cardTag mono">stop = <span class="str">"marker"</span></div>
    <h3>until Claude says done</h3>
    <p>Loops until Claude prints a marker string — <span class="mono">LOOP_DONE</span> by default — on its own line. Best for open-ended work the model itself decides is finished.</p>
  </article>
  <article class="card">
    <div class="cardTag mono">stop = <span class="str">"iterations"</span></div>
    <h3>a fixed number of passes</h3>
    <p>Runs exactly N times with no early exit. Best for scripted refinement where you want a predictable amount of work, not a condition.</p>
  </article>
</div>

  </div>
</section>
